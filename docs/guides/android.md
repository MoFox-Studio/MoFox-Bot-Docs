# 安卓 App 部署

这一篇带你把 Neo-MoFox 装进安卓手机：从下载 App、完成首次引导、创建 Bot 实例，到最后 QQ 扫码上线，全流程都在这里，跟着做就行。

## 它是什么？

**Neo-MoFox 安卓 App** 是 Neo-MoFox 的官方安卓外壳。它最特别的一点是：**App 内自带一整套完整的 Linux 运行环境**（一个名叫 [proot](/docs/guides/glossary#rootfs-与-proot) 的免 root 容器技术，里面跑着 Debian 13 系统，这种系统环境俗称 [rootfs](/docs/guides/glossary#rootfs-与-proot)）。

用人话说：

- 你**不需要**安装 Termux 之类的辅助 App，也不需要 root 手机；
- 下载一个 [APK](/docs/guides/glossary#apk)（安卓安装包）装上，点开就能用；
- 机器人本体和 NapCat（负责连 QQ 的组件，见[名词小课堂](/docs/guides/glossary#napcat)）都在 App 里跑，数据全存在手机本地。

::: tip 一句话总结
这个 App = 一个把「Linux 电脑 + Neo-MoFox + QQ 机器人」整个装进口袋的盒子。装完 App，剩下的活儿它自己会引导你做完。
:::

## 开始之前的准备

开跑之前，先确认这几件事：

| 检查项 | 要求 |
| --- | --- |
| 手机系统 | Android 13（API 33）或更高 |
| CPU 架构 | arm64（近几年的手机基本都是） |
| 剩余存储空间 | 至少 2 GB，建议留更多（要装一整套系统） |
| 可用内存 | 至少 1 GB |
| 网络 | 能上网即可，国内网络也支持（内置加速源） |
| 大模型账号 | 一个[硅基流动（SiliconFlow）](https://cloud.siliconflow.cn)账号，用来拿 [API Key](/docs/guides/glossary#api-key)（驱动 Bot 思考的「钥匙」） |

其中前三项不用你自己记——首次打开 App 时，**系统体检**会自动帮你查一遍（见下文 OOBE 部分）。

## 第一步：下载并安装 APK

目前 App 通过 GitHub 仓库的 Releases（发布页）分发，每晚自动构建一个「Nightly（每夜构建版）」预发布包。

1. 打开 MoFox-Android 仓库的 Releases 页面：<https://github.com/ikun-1145141/MoFox-Android/releases>；
2. 找到 **nightly** 这个预发布（prerelease）条目，展开 **Assets**（附件列表）；
3. 下载文件名里带 **arm64** 的 `.apk` 文件；
4. 下载完成后，在手机上点开这个 APK，系统可能提示「禁止安装未知来源应用」，选择**允许**或按提示授权即可；
5. 等待安装完成，点**打开**。

## 第二步：首次启动引导（OOBE，共四步）

第一次打开 App 会进入 **OOBE**（Out-Of-Box Experience，开箱引导）——它只在你第一次使用时出现，负责把「全局只用做一次」的事统统办好。之后不管你创建多少个 Bot，都不用再走这一遍。

### 第 1 步：欢迎与协议

1. 打开 App，会看到欢迎页，上面列了三个要点：**用户协议**、**隐私政策**、**前台保活**；
2. 想细看的话，点 **阅读最终用户许可协议**（[EULA](/docs/guides/glossary#eula)，即用户许可协议）或 **阅读遥测隐私协议**，会在弹窗里展示全文；
3. 点底部的 **同意并继续**。

隐私政策的核心一句话：所有数据都保存在手机本地的 App 私有目录，不上传任何第三方服务器。

### 第 3 步：解压运行环境（自动执行）

这一步是全流程里最耗时的，但**你什么都不用做**：

1. 进入页面后自动开跑，不用点任何按钮；
2. 依次执行三件事：**解压 Debian 13 系统**（约 290 MB）→ **安装基础依赖**（联网 `apt install`）→ **安装全局 NapCat**（所有实例共用一份，只装这一次）；

4. 全部完成后状态变为 **运行环境就绪**，点 **继续**。

::: warning 耐心等它跑完
这一步受手机存储速度和网络影响，几分钟到十几分钟都正常。期间请**不要杀掉 App、不要重启手机**。如果中途失败（比如网络断了），页面会出现重试按钮，点它从失败处继续即可。

1. 页面列出**通知权限**、**忽略电池优化**、**应用锁定**三项，逐项点 **去授权**；
2. 系统会弹出对应设置页，按提示允许即可（细节见下文[保活体检](#保活体检-让-bot-不掉线)一节）；

## 第三步：创建你的第一个 Bot 实例

[实例](/docs/guides/glossary#实例)就是一只独立的 Bot。App 支持同时管理多个实例，每个实例有自己的名字、QQ 账号和独立目录（`/root/instances/<实例ID>/`）。

### 在哪进入向导？

1. 点底部导航的 **管理** 标签；
2. 首次进入是空页面，提示「点击右下角 创建实例 通过向导部署你的第一个 MoFox Bot」；
3. 点右下角 **创建实例** 按钮，进入全屏八步向导。

向导共八步：**镜像源检测 → 用户协议 → 实例信息 → 账号配置 → 模型配置 → 网络配置 → 确认摘要 → 安装执行**。每步填完点右下角 **下一步** 即可。

### 第 1 步：镜像源检测

1. App 自动测试三个下载源的延迟：**GitHub（官方）**、**GHProxy 加速**、**ikun镜像加速喵**（后两个是国内加速线路）；
2. 稍等片刻，每个源旁边会显示延迟结果，**自动选中最快的那个**；
3. 不满意可以手动点选其他源，然后点 **下一步**。

后面下载 Neo-MoFox 源码、拉取协议文本都用这个源，国内网络建议选加速源。

![图片：向导第 1 步镜像源检测页，三个源与延迟](/guide/android/wizard-mirror.png)

### 第 2 步：用户协议

1. App 会从你刚选的镜像源拉取最新的 **Neo-MoFox 用户许可协议（EULA）**；
2. 阅读后勾选 **我已阅读并同意**；
3. 点 **下一步**。

### 第 3 步：实例信息

1. 在 **实例名称** 输入框里给 Bot 起个名字（必填），比如「小柒」；
2. 点 **下一步**。

### 第 4 步：账号配置

这一步填 Bot 的 QQ 身份，三项里**前两项和第三项中的主人 QQ 必填**：

1. **Bot QQ 号**：机器人要登录的那个 QQ 号；
2. **Bot 昵称（可选）**：机器人对外显示的名字；
3. **主人 QQ**：你自己（管理员）的 QQ 号，拥有最高权限；
4. 点 **下一步**。

::: tip 主人 QQ 填谁的？
填**你自己的** QQ 号。Bot 上线后，你就是它的主人——它可以识别你的指令、执行管理员级别的操作。千万别填成 Bot 自己的号。
:::

### 第 5 步：模型配置

1. 页面显示模型服务已预置为 **硅基流动 SiliconFlow**；
2. 在 **API Key** 输入框粘贴你的密钥（输入框默认打码，点右侧眼睛图标可查看）；还没有的话点下方 **获取密钥**，会跳转浏览器到硅基流动注册/控制台页面；
3. 点 **下一步**。

模型型号和请求地址都帮你预置好了，以后想调整可以随时在 WebUI 里改。

### 第 6 步：网络配置

1. **WebSocket 端口**：Bot 与 QQ 组件通信的端口，默认 **8095**，没特殊需求不用改；
2. **更新通道**：选 **稳定版**（推荐）或 **开发版**（尝鲜，可能不稳定）；
3. **安装 WebUI 管理面板** 开关：建议保持开启，装了之后可以在浏览器里可视化管理 Bot；
4. **WebUI 访问密钥**：点输入框右侧的骰子按钮**随机生成**一个（必填），下方会出现强度条，尽量让它达到「强」；
5. 点 **下一步**。

::: warning 保管好 WebUI 密钥
这个密钥就是 WebUI 管理面板的「门钥匙」，装完后访问 WebUI 要用它登录。截图分享时记得打码。
:::

### 第 7 步：确认摘要

1. 页面汇总你前面填的所有信息：实例名、Bot QQ、主人 QQ、端口、通道、WebUI 等；
2. 发现有填错的，点对应条目可以直接跳回去改；
3. 没问题就点 **开始安装**。

### 第 8 步：安装执行

1. 自动开始安装，页面上彩色日志逐行滚动，上方是任务清单（共 9 个小任务）：克隆 Neo-MoFox 仓库 → 同步 Python 依赖 → 生成配置 → 写入各配置文件 → 安装 WebUI → 写入 NapCat 配置 → 注册实例；
2. 日志区支持**展开/折叠**，想看细节就展开；
3. 全部任务变绿后显示 **安装完成**，点 **完成，返回主界面**。

::: details 安装失败怎么办？
不用慌，失败不会清掉进度。返回 **管理** 页后，那个实例卡片还在，按钮会显示 **继续安装**，点它会从失败的那个任务接着装，前面成功的步骤不用重来。多数失败是网络抖动，换个镜像源重试往往就好了。

## 第四步：启动 Bot 并扫码登录 QQ

### 启动 Bot

1. 进入 **管理** 标签，点你刚创建的实例卡片，进入**实例详情页**；
2. 点 **启动** 按钮，顶部状态灯变化，状态行显示 Bot 进程的运行状态（运行中/已停止等）；
3. Bot 启动需要一点时间（首次启动更久，要初始化环境），看到状态变为运行中即可。

### 扫码登录 QQ

Bot 的「QQ 身份」要靠 NapCat 登录。操作如下：

1. 在实例详情页点 **NapCat** 按钮（NapCat 需要处于运行状态才会弹码）；
2. 页面自动弹出二维码弹窗，提示 **使用 QQ 扫码登录**、**在 QQ → 头像 → 扫一扫 中扫描下方二维码**，下方显示 **等待扫描…**；
3. 打开**手机上的 QQ**（就是 Bot 要登录的那个号），点头像 → **扫一扫**，对准这个码扫一下，在 QQ 里确认登录；
4. 扫码成功后弹窗自动关闭，NapCat 状态变为运行中，Bot 正式上线；
5. 如果二维码过期，App 会**自动刷新**一张新码，不用手动操作；中途想放弃点 **取消登录**。

## 保活体检：让 Bot 不掉线

**国产手机系统（小米、华为、OPPO、vivo、荣耀等）对后台应用下手非常狠，这是 Bot 掉线的头号原因**——不是 Bot 出问题，而是系统把整个 App 杀了。所以保活设置至关重要。

### 在哪体检？

1. 点底部 **设置** 标签；
2. 点 **保活体检** 进入保活状态页；
3. 逐项检查下面五项，全部变绿才安心：

| 检查项 | 干什么用 | 怎么操作 |
| --- | --- | --- |
| **通知权限** | 前台保活服务需要显示一条常驻通知 | 点 **去授权**，允许通知 |
| **忽略电池优化** | 让系统别把 App 当耗电大户清理 | 点 **去设置**，选择允许 |
| **前台保活服务** | 开启后常驻一条守护通知，App 优先级大幅提升 | 点 **开启** |
| **开机自启声明** | 手机重启后 Bot 能自己爬起来 | 此项为声明状态（已声明），实际触发受系统策略限制 |
| **厂商自启动 / 最近任务锁定** | 国产 ROM 的专属后台限制 | 点 **打开设置** 跳到厂商页面，允许自启动，并在最近任务里把 App 锁定 |

安卓厂商的后台策略五花八门且随时变化，App 提供了一键跳转和检查，但**无法承诺 100% 不被杀**。如果你的机型有「电池优化白名单」「后台高耗电允许」之类的隐藏开关，也建议一并打开。Bot 掉线了，先来这里把五项全查一遍。

::: details 各厂商自启动设置在哪？
App 的 **打开设置** 按钮会按手机品牌自动跳到对应的系统设置页（自启动管理 / 耗电管理 / 后台锁定）。如果没跳对，也可以手动找：一般在 **设置 → 应用管理 → MoFox → 电池/自启动** 里。
:::

## 修改主人 QQ 等账号信息

分两种情况：

**还没创建实例**：直接在向导第 4 步「账号配置」里填，最省事。

**实例已经建好了**：目前 App 界面里**没有**改主人 QQ 的按钮（实例详情页只能查看）。改法是编辑配置文件：

1. 进入实例详情页，点顶部的 **实例信息** 图标，在「路径」区找到并复制 **实例目录**（形如 `/root/instances/inst-xxxxxx`）；
2. 打开终端（首页右上角或底部标签）；
3. 编辑该目录下 `Neo-MoFox/config/core.toml` 文件，找到 `[bot]` 段里的 `owner_qq = "..."`，把引号里的号码改成新的主人 QQ；
4. 回到实例详情页，点 **停止** 再点 **启动**，重启 Bot 生效。

::: tip 不想碰命令行？
也可以直接删掉这个实例（实例详情右上角的 **删除实例**，只删实例目录，不动系统和 NapCat），然后重新走向导，两分钟就能重建。
:::

## 更新与升级

- **App 本身的更新**：App 内没有自动更新检查。有新版本时，按[第一步](#第一步-下载并安装-apk)重新下载新 APK 覆盖安装即可，你的实例和数据都会保留；内置系统环境也不会被破坏（版本没变就原样不动）。
- **Bot 本体的更新**（Neo-MoFox 主程序升级、换更新通道等）：在 WebUI 或终端里操作，步骤见 [更新与升级指南](/docs/guides/update)。

## 常见问题

### 解压运行环境特别慢 / 卡住了？

首次进入 OOBE 第 3 步时要解压约 290 MB 的系统包、联网装依赖、再下载安装 NapCat，慢是正常的。存储速度慢、网络不稳都会拖长时间。卡住超过半小时没日志滚动，可以杀掉 App 重开——OOBE 会从断点继续，不会从头再来；NapCat 安装脚本会自动测速挑选 GitHub 加速线路，国内网络也能装。

### Bot 总是掉线 / 后台被杀？

**国产 ROM 杀后台是头号原因**，按这个顺序排查：

1. 进 **设置 → 保活体检**，确认五项全绿（尤其是**忽略电池优化**和**厂商自启动**）；
2. 在系统最近任务界面，把 MoFox 卡片**下拉锁定**（各机型入口略有差异）；
3. 部分机型还要在 **电池 → 后台高耗电 / 应用速冻** 里单独放行；
4. 如果还是被杀，试试在设置里保持**前台保活服务**开启，运行时别用系统清理一键加速。

### 扫码登录失败 / 二维码不出现？

1. 确认点是 **NapCat** 按钮后 NapCat 状态为**运行中**——二维码只在 NapCat 跑起来后才会弹；
2. 二维码过期会自动刷新，多等几秒再看；
3. 用**要登录 Bot 的那个 QQ** 扫，别扫错号；QQ 里确认登录授权后要等它跳转；
4. 还不行就去实例详情的日志标签页翻 **NapCat** 面板，把报错信息对照排查；
5. 网络不好时 NapCat 启动也会慢，切个稳定网络再试。

### 存储占用太大，能清吗？

这套环境确实吃空间：App 自带的系统解压后约 290 MB，加上 Python 依赖、Bot 源码、NapCat 和日志，单实例轻松过 GB。想瘦身的话：

- 删除不用的实例（实例详情 → **删除实例**），只删实例目录，系统和 NapCat 保留，其他 Bot 不受影响；
- 日志会持续累积，定期清理终端里的旧日志文件；
- 彻底清空 = 直接卸载 App（所有数据都在 App 私有目录里，卸载即全清，删前记得导出要留的东西）。
